## 一、软件测试方向

### A1｜完整 JD：测试开发工程师（校招 / 日常实习）

**岗位名称**：测试开发工程师（校招 / 日常实习）｜AI 产品测试方向

**岗位职责**
1. 参与项目测试全流程，根据产品需求和研发设计做需求分析和风险评估，制定测试计划，设计并执行测试用例，定位和跟踪缺陷。
2. 负责自动化测试框架的搭建与优化，编写自动化测试脚本（接口、UI 自动化），提升测试效率和覆盖率。
3. 参与测试环境的搭建、维护与管理，协作开发排查问题；承担日常线下测试与线上质量分析。
4. 参与智能化测试，将传统测试技术与 LLM / Agent 技术深度融合，参与大模型需求解析、用例生成、数据构造、缺陷根因分析。
5. 整理测试报告，输出测试结论，总结测试经验，参与质量改进方案的制定落地。

**任职要求**
1. 统招本科及以上学历，计算机、软件工程等相关专业优先；
2. 掌握至少一种编程语言（Python / Java / C++ 等，优先 Python）；
3. 了解软件测试基础理论、流程和常用测试方法（黑盒、白盒、接口测试等），熟悉用例设计思路；
4. 熟悉 Postman、JMeter、Jira、Git 等工具，数据结构和算法基础较扎实；
5. 具备较强的逻辑思维和问题定位能力，能主动发现并推动解决线上问题。

**加分项**
1. 了解 HTTP/HTTPS 协议、RESTful 接口规范，有接口自动化或性能压测经验者优先；
2. 能熟练使用 Cursor、GitHub Copilot 等 AI 编码助手提效，有把 LLM 引入测试链路的落地经验者优先；
3. 了解 AI Agent 测试、模型基准评测（Benchmark）、大模型用例生成、Prompt 优化者优先。

## 五、经历填写示例库（E1–E9）

> 用法：每人挑**最接近自己真实情况**的一段粘进经历栏，**不要改得比实际好看**——测试价值恰恰在于看知涯面对质量不一的文本怎么判。建议同测两段（最好一段 + 最差一段）。

### E1｜后端项目（信息较完整）
「大三上学期做的校园二手交易平台，我负责后端。Spring Boot + MySQL + Redis，实现了用户、商品、订单、支付、评论 5 个模块、60 多个接口。用 JMeter 压到 500 QPS，商品列表接口 P99 从 820ms 优化到 190ms，主要靠加索引和 Redis 缓存。用 Docker Compose 部署，Git 上有 43 次提交。」
> **测出什么**：能否把「模块数 / 接口数 / QPS / P99 / 优化手段」拆成可量化差距项；能否识别「加索引 + 缓存」属后端核心能力，而非泛泛的「有项目经验」。

### E2｜课程设计（软工背景）
「我们组的软件工程课程设计做了一个智慧选课系统，5 个人，我负责需求分析和数据库设计。写了需求规格说明书和用例图，数据库 8 张表，测试同学照我的用例设计文档跑了 120 多条用例。后来加了 AI 助教问答功能，用 RAG 做了个 demo。」
> **测出什么**：软工专业「需求分析 → 用例设计」这条链能否被识别为**产品岗和测试岗的加分资产**，而非普通课程作业。

### E3｜竞赛经历
「参加过两次数模和一次蓝桥杯。C 组校赛二等奖，主要负责建模和 Python 数据处理那段；蓝桥杯 Java 省级二等奖。另有一个 ACM 训练队经历，做过 100 多道题。」
> **测出什么**：是否把「竞赛获奖」正确映射到开发岗加分项，而非归为「有竞赛但不知道有什么用」。

### E4｜社团运营（偏文科）
「我们社团搞校园二手书交换，我负责运营。每学期办 2 场，场均 200 人左右，用问卷收了 180 多条反馈，做了 3 张数据看板分析换书品类偏好。还负责公众号推文，写过 20 多篇，阅读量最高 3000 多。」
> **测出什么**：产品 / 运营方向能否把「反馈收集 → 数据整理 → 复盘」识别为**可迁移的产品能力**，而非判为「与开发岗无关」。

### E5｜纯文科，无技术经历
「我是汉语言文学专业的，没写过代码，也没做过项目。选过一门 Python 选修课，考了 88 分。平时喜欢看小红书运营的账号，想做内容或者用户方向。」
> **测出什么**：对**非技术背景 + 非技术岗位**的用户，给的是可行入门路径，还是「先学 Java 和 MySQL」这类错配建议。

### E6｜零基础，信息不足（故意）
「 basically 没做过什么项目，就想找个实习。」
> **测出什么**：**不要乱猜**。理想表现是明说「信息不足，补充以下内容才能给建议」，而非虚构经历或套模板。

### E7｜信息不足（故意）
「做过一个网站的作业，就那样。」
> **测出什么**：能否识破「做过」不等于「有产出」，并追问「几个人做的、你负责哪块、有没有上线」——「主动追问」的分水岭。

### E8｜转专业，信息偏少
「我原来是学新闻的，大二转到了软件工程。现在大三，Java 学了一学期，做过一个学生成绩管理的小系统，用的是 Spring Boot，还没部署。」
> **测出什么**：转专业 + 作品不完整时，会不会因「有项目」就判为「已具备项目经验」，从而漏掉真正的差距项（部署、测试、协作）。

### E9｜参与过但不是负责人（容易误判）
「我们团队做了一个校园活动报名的小程序，我是组员，一共 4 个人。我参与写了一些接口，主要是报名和签到这两个功能，大概 8 个接口。我们组还拿了个校级立项。」
> **测出什么**：**重点**——容易把「参与」误判成「已有」独立项目能力，漏掉「缺少独立负责模块」这个真实差距，甚至给出「再做一个项目」的空话。理想表现是追问「你独立负责的部分」。

## 六、测试观察清单（F1–F24）

> 用法：每跑完一轮从上往下扫。**F1–F8 记「系统坏了」，F9–F18 记「AI 说错了」，F19–F24 记「用户想跑」**。

### A. 功能异常

| 编号 | 观察项 | 具体观察方法 |
|---|---|---|
| F1 | 贴长 JD 后卡住 | 贴 A1 后看按钮是否长时间转圈；超 20 秒无响应即异常 |
| F2 | 极简 JD 返回空 | 贴 C1–C4，页面空白或只回「信息不足」且无追问即异常 |
| F3 | 空白输出 | 检查建议区是否出现「无可用建议」或连续空卡片 |
| F4 | 换方向后残留旧结果 | 先贴 A1 生成完再贴 A3，看是否仍显示上次测试岗内容 |
| F5 | 长文本被截断 | 贴 A4 全文，看建议是否还提 Kafka / 可观测性；不提即被截断 |
| F6 | 复制报错 | 复制 JD 到知涯，看是否因换行、编号符号、全角字符解析失败 |
| F7 | 编号错位 | 看提取的岗位名是否正确（如把「加分项」当岗位名） |
| F8 | 重复生成异常 | 同一份 JD 连点两次生成，看第二次是否卡住或报错 |

### B. AI 质量（核心）

| 编号 | 观察项 | 具体观察方法 |
|---|---|---|
| F9 | 编造 JD 里没有的要求 | 对照原文逐条看，凡原文没写的技术点（如「熟悉 Kubernetes」）被列成「岗位要求」即编造 |
| F10 | 编造公司 / 岗位名 | 看建议里是否出现「腾讯」「字节」等输入中没有的公司 |
| F11 | 把矛盾判成信息不足 | 贴 D1–D4，只说「信息不足」而不指出**哪两条互斥**即误判（D 组考察点） |
| F12 | 建议是空话 | 出现「多练习」「提升编码能力」这类无动作、无验收标准的句子即空话 |
| F13 | 建议与方向不匹配 | 贴 A1，看建议是否大量出现「设计表结构」「选型微服务」等后端项 |
| F14 | 非技术用户被劝去学 Java | 贴 B3 / E5，若建议全是「先学 Java、MySQL、Spring」即错配 |
| F15 | 把「参与」判成「已有」 | 贴 E9，看差距页是否仍把「独立负责一个模块」列为待补项 |
| F16 | 把「没做过」猜成「做过」 | 贴 E6 / E7，看建议是否凭空出现「你的项目中…」「你在 XX 中负责…」 |
| F17 | 差距项没有依据 | 打开任一差距项，看能否追溯到 JD 原文哪一句 |
| F18 | 建议不可执行 | 抽查 3 条建议问「今天下午具体做什么」，答不出即空话 |

### C. 体验

| 编号 | 观察项 | 具体观察方法 |
|---|---|---|
| F19 | 差距页有没有虚线卡 | 看是否出现无内容占位的虚线 / 骨架卡片 |
| F20 | 术语没解释 | 同学能否理解「可观测性」「RAG」「幂等」；记下看不懂的词 |
| F21 | 没有下一步 | 建议是否给出具体动作、产出物和自查标准（「写 80 条用例」而非「多写」） |
| F22 | 不知道要贴什么 | 看输入页有无示例 JD / 方向选择 |
| F23 | 想放弃点 | 记录同学在哪一步退出：读 JD、复制、等生成还是看结果 |
| F24 | 看不到「为什么这么判」 | 差距项是否解释「因为 JD 第 3 条要求…，而你目前…」 |

## 七、快速测试脚本（G）｜组织者 5 分钟冒烟

**前置**：4 台设备分测测试 / 开发 / 产品 / 后端方向，另留 1 台测非技术路径。提前把 A1、A3、B3、C1、D1、E5、E9 复制到剪贴板。

| 时间 | 动作 | 通过标准 |
|---|---|---|
| 0:00–0:30 | 打开知涯，**不贴 JD**，先看首屏 | 有明确的 JD 粘贴入口与方向说明 |
| 0:30–1:30 | 同学 1 贴 **A1**，同学 2 贴 **A3** 生成 | 两侧均出结果，不卡住、无空白（F1/F3） |
| 1:30–2:15 | 对比两份结果 | 建议明显不同：测试侧提用例设计 / 自动化框架 / 接口测试，产品侧提 PRD / 原型 / 需求分析 |
| 2:15–3:00 | 同学 3（非中文专业）贴 **B3 + E5** | 能出结果，且建议不是「去学 Java、MySQL」（F14） |
| 3:00–3:45 | 同学 4 贴 **C1**（极简） | 要么给有限但诚实的小建议，要么**主动追问**缺什么；不许编造经历 |
| 3:45–4:30 | 贴 **D1**（矛盾） | 必须指出「零项目经验」与「3 年以上实习经验」互斥，**不能**笼统说「信息不足」 |
| 4:30–5:00 | 贴 **E9**（参与过但非负责人） | 「独立负责模块」应仍在待补项中；建议里不能出现「你的项目已证明具备独立开发能力」 |

**5 分钟末记 4 个数**：① 建议条数；② 不同方向间建议重合比例；③ 出现 F11 / F14 / F15 / F16 硬伤的份数；④ 同学说「看不懂」或「想放弃」的次数。

> 附注：B1–B4 四份非技术岗位 JD 未在调研中单独抓取原文，依据报告中「专业不限、欢迎中文/文学等背景」的真实岗位口径与通用表述改写，仅供测试非技术用户路径，不宜当作某公司的原始 JD。
